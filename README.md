# Personal Activity Time

Требования: Windows 10 версии 2004 (сборка 19041) или новее, .NET 10 Desktop Runtime.

Исправления аудита 02.11.2026 и проверки: [статус исправлений](docs/AUDIT-FIXES.md).

Локальный трекер активности для Windows: «что я делал за компьютером сегодня».
Tray-приложение на WPF собирает активность в локальную SQLite-базу и показывает
дашборд: таймлайн дня, категории, приложения, процессы, CPU/RAM, статистику
недели и месяца.

**Всё локально.** Никакого облака, никакой отправки данных, нажатия клавиш не записываются
(только факт ввода для определения простоя). Приложения из списка исключений (менеджеры
паролей и т.п.) не оставляют в базе ни имени, ни заголовков — только отметку «(исключено)».
Исключения применяются к новым событиям; ранее сохранённая история не удаляется автоматически.

## Быстрый старт

```bash
dotnet run --project src/Pat.App
```

- База: `%LOCALAPPDATA%\PersonalActivityTime\activity.db`
- Настройки: `%LOCALAPPDATA%\PersonalActivityTime\settings.json`
- Посмотреть содержимое базы: `dotnet run tools/DbPeek.cs`

Закрытие окна прячет его в tray. Выход — через меню трея. Автозапуск включается
галочкой в настройках (HKCU `...\Run`, без админ-прав).

## Архитектура

```
Win32-коллекторы -> bounded-очередь -> BufferedEventWriter -> spool -> raw_events (SQLite, WAL)
Browser-расширение -> nativehost/Pat.NativeHost.exe -----------------> raw_events
                                                                       |
                                                                       v
                                                  SessionMaterializer.BuildRange
                                                SessionizationEngine + категории
                                                        |              |
                                              Today / Report / Stats / Export
                                                        |
                                                  sessions (кэш)
```

| Проект | Роль |
|---|---|
| `src/Pat.Core` | Чистое ядро: события, движок сессионизации, правила категорий, экстрактор проекта/файла из заголовков IDE, отчёт дня, нарратив дня и дайджест для LLM. Без Win32 и БД — полностью покрыт тестами |
| `src/Pat.Infrastructure` | Win32-коллекторы (P/Invoke), SQLite: миграции SQL-файлами, Dapper-репозитории, материализатор сессий, StatsService, нормализатор URL, клиент Ollama |
| `src/Pat.NativeHost` | Хост native messaging для браузерного расширения: читает stdin (4 байта длины + JSON), пишет BrowserVisit в ту же базу |
| `src/Pat.App` | WPF + MVVM (CommunityToolkit): вкладки «Сегодня», «Отчёт» (нарратив + локальная LLM), «Статистика», ScottPlot-графики, tray (H.NotifyIcon), оркестратор TrackingService |
| `extension/` | Расширение Chrome/Edge (MV3): активная вкладка → native messaging. Установка — см. `extension/README.md` |
| `tests/Pat.Core.Tests` | Тесты ядра, SQLite, восстановления записи, настроек, жизненного цикла Win32/TrackingService и WPF-графиков |
| `tools/DbPeek.cs` | Файловое приложение .NET 10: содержимое базы в консоль |

### Почему tray-приложение, а не сервис

Сервисы Windows живут в session 0 и не видят пользовательский стол: ни `GetForegroundWindow`,
ни заголовков окон, ни `GetLastInputInfo`. Всё связанное с активностью пользователя должно
собираться процессом в его сессии — поэтому один WPF-процесс с tray-иконкой и автозапуском.

### Как собираются данные

- **ForegroundCollector** — `SetWinEventHook(EVENT_SYSTEM_FOREGROUND | EVENT_OBJECT_NAMECHANGE)`
  в собственном потоке с message loop + страховочный опрос `GetForegroundWindow` раз в секунду.
  Сигналы дедуплицируются по (путь exe + нормализованный заголовок). Путь к exe берётся через
  `QueryFullProcessImageName` с `PROCESS_QUERY_LIMITED_INFORMATION` — работает и для процессов
  с повышенными правами, без админа.
- **IdleMonitor** — опрос `GetLastInputInfo` каждые 5 с. `IdleBegan` датирован моментом
  последнего ввода, `IdleEnded` — моментом нового (не моментом обнаружения). После
  разблокировки/пробуждения состояние сбрасывается: пароль вводится на secure desktop
  и в last-input не попадает.
- **SessionMonitor** — `SystemEvents.SessionSwitch` (lock/unlock) и `PowerModeChanged`
  (suspend/resume) как границы валидности сессий.
- **ProcessSnapshotCollector** — запуск/останов процессов дифом снимков
  `CreateToolhelp32Snapshot` каждые 3 с (без админ-прав; WMI-трейсы и ETW требуют
  админа). Один снимок даёт pid + ppid + имя exe; смена exe у живого pid трактуется
  как PID reuse (stopped + started). Имя родителя денормализуется в payload — дерево
  процессов строится прямо из журнала. Командные строки не собираются: для них нужен
  PEB/WMI, что падает на elevated-процессах.
- **SystemMetricsCollector** — сэмпл каждые 30 с: CPU% через `GetSystemTimes`
  (диф между сэмплами, без PerformanceCounter), RAM через `GlobalMemoryStatusEx`.
  Payload JSON в `raw_events`.

- **FileActivityCollector** — наблюдение за выбранными в настройках корнями
  (FileSystemWatcher, рекурсивно). События дебаунсятся в буфере (на одно сохранение
  FSW шлёт пачку), служебные каталоги (bin/obj/node_modules/.git/Temp/...) и
  временные файлы (~$, .tmp, .swp) отфильтровываются; собственные файлы трекера
  исключены всегда. Виды: создан/изменён/удалён/переименован (с OldPath).
- **Браузер** — расширение Chrome/Edge (папка `extension/`) шлёт активную вкладку
  в `Pat.NativeHost.exe` через native messaging; хост извлекает домен, дедуплицирует
  и пишет `BrowserVisit` в ту же базу. Не-web схемы (chrome://, file://) не
  записываются. Регистрация хоста — кнопкой в настройках (манифест + HKCU-ключи
  Chrome и Edge, без админ-прав). Пока трекинг на паузе, хост ничего не пишет
  (файл-маркер). Подробности установки: `extension/README.md`.

### Отчёт дня и локальная LLM

Вкладка «Отчёт» показывает **нарратив дня** — реконструкцию контекста из журнала
(работает локально, без всякой LLM):

- соседние сегменты с разрывом до 4 минут склеиваются в отрезки работы — быстрый
  alt-tab в мессенджер или браузер за документацией контекст не рвёт;
- заголовок отрезка выводится из доминирующего проекта в IDE-заголовках
  («Работа над WaferAnalyzer») или из категории;
- в деталях отрезка — категории и приложения, домены браузера с числом визитов,
  созданные/изменённые файлы;
- итоги: самый длинный непрерывный отрезок, число смен контекста.

**Локальная LLM (опционально, выключена по умолчанию).** Кнопка «Что я сегодня
делал?» отправляет в Ollama компактный агрегированный дайджест дня (категории,
приложения, отрезки — не сырые события) и возвращает рассказ о дне. Можно задать
и свой вопрос. Интеграция требует установленной [Ollama](https://ollama.com):
укажите сервер и модель, нажмите «Проверить» (кнопка подставит первую доступную
модель). Принимаются только loopback IP-адреса (по умолчанию `127.0.0.1:11434`),
данные не покидают машину; think-блоки reasoning-моделей (qwen3 и т.п.) вычищаются.

### Журнал — источник истины

`raw_events` append-only: события никогда не перезаписываются. `sessions` — материализованный
кэш, пересобираемый из журнала текущего дня раз в пять секунд, при смене правил,
паузе и выходе. UI, статистика и экспорт строят интервалы напрямую из журнала,
поэтому отсутствие кэша не приводит к пустому экспорту.

Состояние восстанавливается от последнего начала запуска перед периодом, а для
старой истории — из доступных событий. Интервалы обрезаются по обеим границам,
текущий день — по текущему времени. Start/stop/heartbeat ограничивают время работы
трекера; оценка аварийного завершения описана в статусе исправлений аудита.

Категории задаются регексами по имени exe / пути / заголовку окна в `settings.json`
(`CategoryRules`; отсутствие поля = встроенный набор: Программирование, Браузер, Общение,
Игры, Файлы, Медиа). Меньше `Priority` — выше приоритет; без совпадения — «Другое».

### Надёжность

- **Файловое логирование.** Все ошибки записи в БД, материализации и наблюдения
  файлов попадают в `%LOCALAPPDATA%\PersonalActivityTime\error.log` (потокобезопасно,
  файл открывается с `FileShare.ReadWrite`, поэтому приложение и NativeHost не мешают
  друг другу). При превышении 1 МБ лог ротируется в `error.log.1` — максимум 2 МБ на диск.
- **Наблюдение файлов самовосстанавливается.** Переполнение внутреннего буфера
  `FileSystemWatcher` не глушит наблюдение до перезапуска: watcher пересоздаётся
  для того же корня через 5 секунд, потеря ограничена моментом сбоя.
- **Восстановление записи.** Переполнение очереди задерживает производителей вместо
  удаления старых событий. Writer сохраняет батчи в spool до подтверждения SQLite;
  повторная отправка после аварии не создаёт дубли. Отказ диска останавливает сбор.

### Владение данными

- **Экспорт.** Кнопка «Экспорт дня» в шапке и «Экспорт периода» на вкладке
  «Статистика» сохраняют сессии в CSV (разделитель `;`, UTF-8 с BOM — открывается
  в Excel с кириллицей) или JSON. Экспортируется то, что в базе: категории,
  приложения, заголовки, проекты, флаги простоя/исключения.
- **Срок хранения (retention).** Настройка «Хранить данные» (по умолчанию 180 дней,
  «вечно» = 0): при старте и раз в сутки журнал и сессии старше срока удаляются,
  WAL усекается; свободные страницы основного файла переиспользуются SQLite.
  Кнопка «Очистить старые данные» делает то же немедленно и показывает изменение размера.
- **Автозапуск без рассинхрона.** `StartWithWindows` в settings.json — источник
  истины: при каждом старте запись в реестре (`HKCU\...\Run`) синхронизируется,
  устаревший путь к exe чинится автоматически.

## Тесты

```bash
dotnet test
```

Движок сессионизации покрыт сценариями: смена окон, простой с точной датировкой,
блокировка/сон/пауза, переоткрытие окна после простоя, склейка соседних сегментов,
исключённые приложения, обрезка по границам суток, журнальные события процессов и метрик.
Интеграционные прогоны на реальной SQLite: полный конвейер, идемпотентность
материализации, payload round-trip, восстановление состояния через полночь,
многодневная агрегация, rollback и повтор записи после сбоя.
