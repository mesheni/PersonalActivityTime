## Гарантии и ограничения

- Writer складывает полученные события в `%LOCALAPPDATA%\PersonalActivityTime\pending-events`
  до подтверждения SQLite, обычно не реже раза в секунду. После успешного commit файл
  удаляется; квитанция commit предотвращает дубли при аварии между commit и удалением.
  Передача flush подтверждает запись всех предшествовавших ему событий.
- При временной недоступности SQLite события остаются в spool и запись повторяется.
  При отказе самого spool сбор останавливается, ошибка отображается в подписи кнопки
  паузы и журнале. Недоступный диск не позволяет гарантировать сохранение ещё не
  записанной части очереди; после устранения причины нужен перезапуск.
- Start/stop задают точные штатные границы. Heartbeat поступает раз в пять секунд;
  незакрытый текущий запуск ограничен последним heartbeat плюс 15 секунд. После
  следующего start предыдущий аварийный запуск заканчивается последним heartbeat.
  Этот предел — оценка, а не точное время аварии.
- Старая история без start/stop остаётся доступной, но отсутствующие границы прошлых
  запусков и потерянные старой версией батчи восстановить точно нельзя.
- Настройки резервируются в `settings.json.bak`. Если ни основной файл, ни backup
  не читаются, App показывает сообщение и не запускает сбор до сохранения настроек;
  NativeHost при ошибке настроек не записывает визиты.
- Ollama: используйте `http://127.0.0.1:11434` или IP `::1`; внешние серверы и имена
  DNS намеренно не поддерживаются локальным режимом.
- Миграция 002 удаляет только некорректные производные sessions и добавляет ограничения;
  миграция 003 добавляет квитанции батчей. Исходный raw_events не переписывается.
- Retention удаляет старые события/сессии и больше не нужные приложения. Checkpoint
  освобождает WAL; основной файл SQLite переиспользует страницы и не обязан уменьшаться.
  Spool, квитанции дедупликации и backup настроек — служебные данные восстановления.

## Проверки

```powershell
rtk dotnet test PersonalActivityTime.slnx --verbosity minimal
rtk dotnet build PersonalActivityTime.slnx -c Release --verbosity minimal
rtk dotnet publish src/Pat.App/Pat.App.csproj -c Release -o artifacts/audit-fixed --verbosity minimal
rtk dotnet run --project tools/AuditProbe/AuditProbe.csproj
```

Все девять сценариев AuditProbe после исправлений дают ожидаемые результаты.
Полный набор: 112 тестов пройдено. Release-сборка: 0 ошибок, 0 предупреждений.
Проба A08 теперь содержит добавленные продуктом границы запусков; A06 использует
тот же путь построения, что исправленный экспорт.

Проверки выполняются на временных БД и синтетических данных. Фактическая установка
расширения в пользовательский браузер, блокировка/сон Windows и автозапуск при входе
не выполнялись. Для приёмки на устройстве остаются эти сценарии из FIX-PLAN.md.

Дополнительные пункты исходного аудита, которые требуют отдельной работы: профилирование
больших баз и всех UI-запросов, полнота топов/нарратива при лимите 400/500 фактов,
уплотнение основного файла SQLite и политика хранения служебных квитанций. Они не
объявляются закрытыми исправлениями F01–F16.
